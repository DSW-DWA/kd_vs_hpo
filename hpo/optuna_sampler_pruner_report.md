# Optuna Samplers And Pruners

## Samplers

Sampler отвечает за выбор новых гиперпараметров для trial.

Он решает:

```text
какие значения lr, weight_decay и других гиперпараметров попробовать дальше
```

### RandomSampler

Случайно выбирает значения из заданного пространства поиска.

Подходит как простой baseline. Не использует результаты прошлых trial.

Как работает:

```text
для каждого trial случайно берет значения из заданных диапазонов
```

### TPESampler

Tree-structured Parzen Estimator.

Использует историю прошлых trial и чаще предлагает значения из областей, где уже были хорошие результаты.

Обычно это основной практический sampler в Optuna.

Как работает:

```text
делит прошлые trial на хорошие и плохие
строит распределения для обеих групп
выбирает новые значения, похожие на хорошие trial и непохожие на плохие
```

### GPSampler

Gaussian Process sampler.

Строит вероятностную модель зависимости между гиперпараметрами и качеством модели.

Может быть полезен, когда каждый trial дорогой, но сам sampler может работать медленнее TPE.

Как работает:

```text
оценивает, где качество может быть высоким
оценивает, где модель еще не уверена
выбирает следующую точку с учетом качества и неопределенности
```

### CmaEsSampler

Использует алгоритм CMA-ES.

Хорошо подходит для непрерывных числовых параметров. Может быть полезен, когда нужно оптимизировать несколько связанных вещественных гиперпараметров.

Как работает:

```text
держит распределение возможных решений
сэмплирует из него новые trial
после оценки trial сдвигает распределение в сторону лучших решений
```

### NSGAIISampler

Sampler для multi-objective optimization.

Используется, когда нужно оптимизировать несколько целей одновременно, например:

```text
accuracy maximize
FLOPs minimize
```

Как работает:

```text
ищет не одно лучшее решение, а набор компромиссных решений
оставляет решения, которые не хуже других сразу по всем целям
```

### NSGAIIISampler

Расширение NSGA-II для задач с большим числом целей.

Нужен редко, в основном для сложной multi-objective оптимизации.

Как работает:

```text
похож на NSGA-II
дополнительно использует reference points, чтобы равномернее покрывать многоцелевое пространство
```

### QMCSampler

Quasi-Monte Carlo sampler.

Похож на random search, но пытается покрывать пространство поиска более равномерно.

Полезен, когда нужно систематично исследовать пространство гиперпараметров.

Как работает:

```text
генерирует не полностью случайные точки
точки распределяются по пространству более равномерно, чем при обычном random search
```

### GridSampler

Перебирает заранее заданную сетку значений.

Полезен, если нужно проверить конкретные комбинации гиперпараметров.

Минус - плохо масштабируется при большом числе параметров.

Как работает:

```text
заранее строит все комбинации значений
затем последовательно запускает trial для каждой комбинации
```

### PartialFixedSampler

Фиксирует часть гиперпараметров, а остальные передает другому sampler.

Полезен, если часть параметров уже выбрана, а остальные еще нужно оптимизировать.

Как работает:

```text
одни параметры всегда возвращает фиксированными
остальные параметры выбирает через базовый sampler, например TPE или Random
```

### BruteForceSampler

Перебирает все возможные варианты в дискретном пространстве поиска.

Подходит только для маленьких пространств, где полный перебор реально выполнить.

Как работает:

```text
строит дерево всех возможных дискретных вариантов
запускает trial для каждой еще не проверенной ветки
```

## Pruners

Pruner отвечает за раннюю остановку плохих trial.

Он решает:

```text
продолжать trial или остановить его раньше времени
```

### NopPruner

Ничего не останавливает.

Все trial обучаются до конца.

Полезен как baseline, чтобы понять качество без early stopping.

Как работает:

```text
на каждый запрос should_prune всегда отвечает false
```

### MedianPruner

Останавливает trial, если его промежуточный результат хуже медианы предыдущих trial на той же эпохе.

Простой и понятный pruner.

Как работает:

```text
смотрит результат текущего trial на данной эпохе
сравнивает его с медианой прошлых trial на той же эпохе
если текущий trial хуже медианы, он может быть остановлен
```

### PercentilePruner

Похож на MedianPruner, но использует заданный percentile вместо медианы.

Например, можно останавливать trial, которые хуже 75% предыдущих trial.

Как работает:

```text
считает заданный percentile по прошлым trial
останавливает текущий trial, если он хуже этого порога
```

### SuccessiveHalvingPruner

Optuna-аналог ASHA.

Trial обучается до контрольных уровней ресурсов, например:

```text
3 epochs
9 epochs
27 epochs
81 epochs
```

На каждом уровне слабые trial останавливаются, а сильные продолжаются.

Важно: в Optuna это асинхронный pruner. Он не обязан сначала обучить все trial до 3 эпох.

Как работает:

```text
задает уровни ресурсов: 3, 9, 27, 81 epochs
на каждом уровне сравнивает trial между собой
слабые trial останавливает
сильные trial пропускает на следующий уровень
```

### HyperbandPruner

Расширение Successive Halving.

Запускает несколько стратегий распределения бюджета: где-то пробует больше trial коротко, где-то меньше trial, но глубже.

Хороший выбор, если заранее непонятно, сколько эпох нужно давать одному trial.

Как работает:

```text
создает несколько Successive Halving схем с разной глубиной
одни схемы проверяют много trial коротко
другие проверяют меньше trial, но дольше
затем лучшие trial получают больше ресурсов
```

### ThresholdPruner

Останавливает trial, если метрика хуже заданного порога.

Пример:

```text
остановить trial, если val_acc1 < 50% после 3 эпох
```

Как работает:

```text
сравнивает промежуточную метрику с заданным порогом
если метрика хуже порога, trial останавливается
```

### PatientPruner

Останавливает trial, если метрика долго не улучшается.

Похож на early stopping с patience.

Как работает:

```text
следит за улучшением метрики
если улучшения нет заданное число проверок подряд, trial останавливается
```

### WilcoxonPruner

Использует статистический тест Wilcoxon для сравнения trial.

Может быть полезен, когда метрика шумная, но обычно сложнее для интерпретации.

Как работает:

```text
сравнивает последовательность промежуточных результатов текущего trial с другими trial
если статистически видно, что trial хуже, он останавливается
```

## Что используем в эксперименте

В текущем эксперименте сравниваются:

```text
RandomSampler + SuccessiveHalvingPruner
TPESampler    + SuccessiveHalvingPruner
TPESampler    + HyperbandPruner
GPSampler     + SuccessiveHalvingPruner
GPSampler     + HyperbandPruner
```

Для нашей задачи:

```text
Sampler = какие гиперпараметры попробовать
Pruner  = какие trial остановить раньше
```
